1Introduction

sgcFSearch is a whole-disk file search tool for Windows. It keeps an index of the names of every file and folder on your fixed drives, answers queries in milliseconds while you type, and keeps the index current while files change. A search bar opens with a global hotkey, the sgcfs command line client gives the same results in a terminal, and a local named pipe API lets other programs ask questions too.

Besides file names, sgcFSearch can search the text inside files located in your content folders (your user folder by default), including Office documents and, through Windows filters, PDF files.

sgcFSearch is modelled on scry and inspired by fsearch. It is an independent implementation written in Delphi.

Main features

  • Name index of every fixed drive, built by a multi-threaded crawler on the NT directory API and saved to names.idx for fast restarts.
  • Live updates while the app runs, plus a catch-up through the NTFS change journal (USN journal) for changes made while it was closed. No administrator rights are needed.
  • Search bar on a global hotkey with ranked results, file icons, highlighted matches, filter chips, search history, open, show in folder and copy.
  • Typo tolerant matching and a rich query syntax: name modifiers, path tokens, extension, type, kind, folder scope, path text, size, modified date, regular expression, limit and sort filters.
  • Ranking that learns from the files you open or copy (frecency).
  • Content index of the files under your content folders, searched with grep:, regex: and sym:.
  • sgcfs command line client with plain, long and JSON output, a JSON lines bridge, status, stop, show, install, uninstall and bench commands.
  • Named pipe API (one JSON object per line) restricted to the current user.
  • Tray icon with the index status, a Folders dialog, Start at login and the daemon log.
  • Two downloads, both digitally signed: a per user installer (recommended) and a zip for a manual installation. No administrator rights are needed.

With the manual installation, two optional commands of sgcfs set this up for the current user. The setup does the same through its two tasks.

Note. Open a new terminal after sgcfs install. Terminals that were already open do not see the new PATH entry. If you move the folder later, run sgcfs install again from the new location.

Uninstall

Installed with the setup. Uninstall sgcFSearch from the Windows Settings app, under Apps. The uninstaller:

  • stops the running app with sgcfs stop,
  • removes the program files and the Start menu shortcut,
  • removes the install folder from the user PATH,
  • removes the sgcFSearch login entry from the Run key, also when the tray menu created it.

Installed manually from the zip.

  1. Run sgcfs uninstall. It removes the login entry and removes the folder of sgcfs.exe from the user PATH.
  2. Quit sgcFSearch from the tray menu.
  3. Delete the folder you unzipped.

In both cases the data folder %LOCALAPPDATA%\sgcFSearch (index, settings, history, usage, log) is kept. Optionally delete it by hand to remove every trace.

Note. Do not use both ways side by side. A copy from the zip and a copy from the setup would share the same data folder and the same login entry, and the PATH could point to either one. Uninstall the one you do not want before you use the other.

Portable mode

Portable mode is for the zip, not for the installed version. Create an empty file named sgcFSearch.portable next to sgcFSearch.exe and that copy becomes portable. The file alone turns it on, its content does not matter and there is no command line switch. A file named sgcFSearch.portable.txt also works, for example when Notepad adds the extension and Windows hides it. The file wins over SGCFSEARCH_HOME, and a folder with either name does not count.

ItemIn portable mode
Data folderdata\<computer name> inside the program folder. Each computer has its own folder, so one copy on a USB stick used on several PCs never mixes indexes.
Outside the folderNothing is written outside the program folder. The tray item Start at login is disabled, and sgcfs install and sgcfs uninstall print a message and exit with code 2.
Installed copyA portable copy runs independently of an installed one on the same PC. It has its own pipe, and its sgcfs talks only to it. If the installed copy holds the hotkey, the portable copy uses a fallback hotkey.
Note. The program folder must be writable. On read-only media nothing can be saved, and a computer with no index there yet gets one scan that can be searched, then the tray shows Stopped and later changes are not followed.

3Getting started

First run

Start sgcFSearch from the Start menu entry created by the setup, or run sgcFSearch.exe from the folder where you unzipped it. The sgcFSearch icon appears in the notification area of the taskbar. When you start the app yourself, without --background, the search bar also opens right away.

On the first run there is no index yet, so sgcFSearch crawls every fixed drive. While it crawls:

  • the tray tooltip reads sgcFSearch: Indexing N entries,
  • the status line of the search bar reads Indexing... N files,
  • you can already search. Results come from the part of the disk crawled so far and refresh as the index grows.

When the crawl ends, the index is saved to names.idx and the state becomes Ready. Then the content indexer starts and reads the files of your content folders in the background, at low priority. While it works, the tray tooltip adds N files being read.

On later starts, sgcFSearch loads names.idx, catches up with the changes made while it was closed, and is ready in about a second.

Index states

State (pipe, sgcfs status)Tray tooltipSearch bar statusMeaning
startingLoading indexStarting...The engine is starting.
loadingLoading indexLoading index...names.idx is being read.
crawlingIndexing N entriesIndexing... N filesFirst run (or no usable index): the drives are being crawled.
catchupUpdating, N files, N foldersUpdating index...Changes made while the app was closed are applied. Drives listed in the settings but missing from the index are crawled.
readyReady, N files, N folders(nothing)The index is complete and watched for changes.
stopping, stoppedStopping, StoppedIndex stoppedThe app is saving its index and closing.

Searches work in every state.

The hotkey

Press Alt+Shift+Space to show the search bar. Press it again, or Esc, to hide it. If another program already owns that hotkey, sgcFSearch tries Win+Shift+F and then Ctrl+Alt+F. The hotkey in use is shown next to Search in the tray menu and written to the log. You can choose another hotkey in the Folders dialog.

A left click on the tray icon, the tray menu item Search and sgcfs show also open the bar.

A first search

  1. Press Alt+Shift+Space.
  2. Type part of a file name, for example invoice. Results appear as you type, best matches first.
  3. Narrow it down: invoice ext:pdf mtime:month shows PDF files with "invoice" in the name modified in the last 30 days.
  4. Use Up and Down to select a result and press Enter to open it, or Ctrl+Enter to show it in its folder.

The same search from a terminal:

sgcfs invoice ext:pdf mtime:month

Filter chips

The chips are a mouse friendly way to write filters. Each chip reads and writes one filter in the search box, so a filter you type by hand also lights up its chip. Choosing an option replaces the current value of that filter. Remove filter, at the bottom of the menu of an active chip, deletes it.

ChipMenu optionWrites into the query
TypeDocuments, Images, Videos, Audio, Code, Archives, Apps, Fontstype:documents, type:images, type:videos, type:audio, type:code, type:archives, type:apps, type:fonts
Folderstype:folders
ModifiedToday, Yesterday, Past week, Past month, Past yearmtime:today, mtime:yesterday, mtime:week, mtime:month, mtime:year

SortRelevance, Name, Size, Date, DirectoryRelevance removes sort:. The others write sort:name, sort:size, sort:date, sort:dir

An active chip shows its value: the Type chip lists the categories (for example Images, Code), the In folder chip shows In and the folder name, and the Sort chip shows Sort: Name.

The Saved chip has no filter of its own and never turns blue. It keeps the searches you repeat, each one a name and a query such as ext:pas in:C:\Projects mtime:week. Its menu lists the saved filters in alphabetical order, then Save current search..., which asks for a name and is disabled while the search box is empty, then a Remove submenu. A name that already exists, ignoring case, is replaced.

Choosing a saved filter writes it into the search box and runs the search. The words you typed stay. Each filter key in the saved text replaces every filter of that key in the box, and a key the saved text holds more than once, such as in: or path:, keeps all its values. Plain words in the saved text are added if they are not already there, so applying the same filter twice changes nothing. The list is stored in saved_filters.json in the data folder, so it survives updates and follows portable mode.

History

The bar remembers your last 50 searches in history.json in the data folder. A search is added when the bar closes with text in the box, and when you copy a file or a path. Repeating a search moves it to the top instead of adding a duplicate.

With an empty search box, press Up to recall the most recent search, and keep pressing Up for older ones. Down goes back toward the newest one and finally to an empty box. As soon as you edit the recalled text, the arrow keys move the selection again.

Moving and pinning

Drag the bar by its empty area, that is the outer margins, the space between the chips and the status text, to move it. The position is remembered for each monitor layout, so docking and undocking a laptop gives each layout its own place. A position that is no longer on screen is ignored. When the results would take the bar past the bottom of the work area, it is shifted up for display and the remembered position does not change. Double-click the empty area to forget the position for the current monitor layout and center the bar again.

The pin button at the right end of the search box is the Keep open toggle. When it is on:

  • the bar does not hide when it loses the focus, and it no longer stays on top of other windows,
  • opening a result, showing it in its folder and copying leave the bar open,
  • Esc still hides the bar,
  • the hotkey and the tray icon bring the bar to the front with the focus in the search box, or hide it when it is already the active window,
  • the results keep refreshing while the bar is in the background.

The pin state and the positions are saved in bar.json in the data folder and are kept across restarts and updates.

Folder picker

Two ways lead to the standard Windows folder dialog:

  • the In folder... chip, menu item Choose folder..., which sets the in: filter,
  • typing in: or path: and pressing Tab while the cursor is on that token. The chosen folder is inserted after the colon, in double quotes when it contains spaces.

5Query syntax

A query is a list of words and filters separated by spaces. Every word must match the name of the file or folder (not its path), case-insensitive. Filters have the form key:value. Only the keys listed in the filter reference are filters: any other text:text token is searched as a plain word. The order of words and filters does not matter.

Words and modifiers

SyntaxMeaningExample
wordThe name contains the word, case-insensitive. Tolerates one typo for words of 5 letters or more.budget
w1 w2All words must match (AND).budget 2026
'exactThe whole name equals the word.'readme.md
^prefixThe name starts with the word.^setup
suffix$The name ends with the word..bak$
^both$Same as 'exact.^desktop.ini$
!wordExclude names that match. Combines with the other modifiers.!^tmp, !.log$
"two words"Double quotes keep spaces inside one word. Modifier characters inside quotes are taken literally."annual report"
*, ?Wildcards: * matches any run of characters (also none), ? exactly one character. The pattern matches the whole name, with no typo tolerance.*.pas, report*, a?c

A word with * or ? is a wildcard pattern: *.pas finds names ending in .pas, report* names starting with report, *report* names containing it, and a?c three character names such as abc or a1c. Wildcards also work inside double quotes and in the last part of a path token (src\*.pas), since * and ? cannot appear in a file name. Filter values are not affected.

Matching is on the name only. To match folder names along the path, use path tokens, in: or path:.

Typo tolerance

A plain word of 5 or more letters also matches a name that contains it with one error: one letter missing, one letter extra, one letter different, or two neighbour letters swapped. confgi finds config.json, raport finds report.pdf. Typo matches get the lowest match tier, so they normally rank below exact matches. Words shorter than 5 letters, and words with ', ^ or $, must match exactly.

Path tokens

A word that contains \ or / is a path token. Its last part matches the name, and the earlier parts must match the names of ancestor folders, in that order, as substrings.

TokenFinds
src\mainNames containing main below a folder whose name contains src
photos\2026\beachNames containing beach below a 2026 folder below a photos folder
node_modules\Anything below a folder whose name contains node_modules
docs/^introForward slashes work too, and modifiers apply to the last part

Filter reference

Filter keys are case-insensitive. Put the value in double quotes when it contains spaces, for example in:"C:\My Projects".

FilterValueMeaningExamples

When a filter is given twice, ext: and type: add to the list, in: widens the scope, path:, size: and mtime: must all hold, and for kind:, re:, limit:, sort:, grep:, regex:, sym: and case: the last one wins. If a query has more than one content filter, grep: is used first, then regex:, then sym:.

An invalid value never stops the search. It is ignored and reported in the status line, for example invalid size: 10q, unknown type: pics, invalid mtime: lastweek or empty value: ext:.

The home folder ~

In in: values, and in the content folders and skip list of the settings, a leading ~ stands for your user folder (%USERPROFILE%, for example C:\Users\you). Use ~ alone or followed by a backslash: in:~, in:~\Documents.

Units are b (default), k, kb, kib, m, mb, mib, g, gb, gib, t, tb, tib, all 1024 based. Decimals are allowed: size:>1.5g.

6Content search

What is indexed

Content search looks inside files that are located below the content folders. The default content folder is ~, your user folder. Change the list in the Folders dialog or in the roots key of config.json.

When the name index is ready, a background thread at low priority reads the files below the content folders and builds a trigram index of their text in content.idx. After a restart, only files whose size or modified time changed are read again. While the app runs, changed files are queued and read again automatically.

  • Size cap. Files larger than content_max_size_mb (default 16 MB) are not content indexed.
  • Cloud files. Online-only files from OneDrive and other cloud providers (offline or recall-on-access placeholders) are never opened, because opening them would download them.
  • Skip list. Nothing below a folder in the skip list is indexed, neither names nor content.
  • Links and denied folders. Junctions, symbolic links and mount points are not followed. Folders that cannot be opened (access denied) are left out.
  • Excluded folder names. Files inside folders with these names are never read for content (their names are still searchable):

Case. Content search ignores case by default: grep:todo and grep:TODO both find "TODO" and "todo". A capital letter in the search text changes nothing.

Add case:yes (case-sensitive) or case:no (ignores case) to decide for one search, in any mode: grep:TODO case:yes finds only "TODO". File name matching always ignores case.

To change the default, set content_case in config.json. sensitive is always case-sensitive. smart is the previous behaviour: a search text with an uppercase letter is case-sensitive, and in regex: and sym:, escaped sequences such as \W do not count as uppercase. The value is kept across updates, because config.json is in the data folder, and it takes effect at the next start.

Results. Each hit line is one result, with the file, the line number and the line text. Up to 5 lines are reported per file, and the limit counts lines, not files. Every candidate file is read again at search time to confirm the match, so results never come from stale index data. In the bar, content rows show line N: and the text.

Tip. Quote patterns with spaces: grep:"connection string", regex:"class \w+Helper".

Combining with name filters

Name filters also apply to content results: grep:TODO ext:pas in:~\Projects searches only Pascal files below that folder. Plain words in a query with a content filter must also appear in the file name: grep:TODO engine searches for "TODO" only in files whose name contains "engine".

Automatic fallback

When a query has plain words and no content filter, and no file or folder name matches, sgcFSearch searches the content instead: it looks for files below the content folders that contain every word, and reports the lines that contain any of them. Name filters still apply. The bar then shows No file name matches, showing matches inside files, and the pipe response has "content":true.

7Ranking

Match quality

Each word gets a quality tier for each name. With several words, the weakest word decides the tier of the result.

TierQualityExample for the word report
5Exact: the whole namereport
4Prefix: the name starts with the wordreport-2026.pdf
3Word start: the word starts after a separator such as . _ - or a space, at a letter and digit change, or at a camelCase stepannual_report.pdf, AnnualReport.docx
2Substring anywhere in the namemyreports.txt
1Typo match (one error)raport.pdf

The score

With the default sort:rank, results are ordered by a score:

score = 100 x tier
      - 2 x folder depth (depth counted up to 40)
      + usage bonus (0 to 60, see Frecency)
      + 1 when the first word matches with the exact letter case

The tier dominates: one tier is worth 100 points, while the depth penalty is at most 80 and the usage bonus at most 60. Items closer to the drive root rank above deeply nested ones, and files you use often move up. Ties go to the shorter name. The other sort orders use their own field first and the score to break ties.

Frecency

sgcFSearch remembers the files you open and copy, in usage.json in the data folder. Each use adds a weight that halves every 14 days:

ActionWeight
Open (Enter, double-click, Open menu), Show in folder, a pipe use request with "kind":"open"1.0
Copy file (Ctrl+C), a pipe use request with "kind":"copy"0.7

The usage bonus is 10 x ln(1 + sum of the decayed weights), capped at 60. A file used often and recently gets a large bonus, one used long ago fades out. Up to 4,000 paths are remembered, the lowest scores are dropped first. Copy path does not count as a use.

See Sort values for the other orders.

12How it works

Architecture

The crawl

The crawler lists folders with the native NT API: each folder is opened relative to its parent handle (NtOpenFile) and listed in bulk, many entries per call, instead of one FindNextFile call per file. Several threads crawl in parallel. Junctions, symbolic links and mount points are recorded but not entered, which avoids loops and duplicates. Folders that cannot be opened are marked as denied, folders in the skip list are never opened, and cloud placeholder folders are crawled and marked as offline.

Before a drive is crawled, its change journal position is stored. After the crawl, the changes made during the crawl are applied from the journal, so nothing is missed.

The name index

The index lives in memory: one compact record per file or folder (parent, first child, next sibling, name, size, modified time, flags), with the names stored once in a shared pool. Searches scan it on several threads and keep only the best results, which is why a query over millions of names takes milliseconds. The index is saved to names.idx together with the journal position of each drive, and loaded in about a second at the next start.

Live updates

  • While running. A watcher per drive uses ReadDirectoryChangesW on the whole drive. Changed folders are listed again and the differences applied. Renamed and moved folders keep their contents. A change is visible in searches within a fraction of a second.
  • Buffer overflow. When too many changes arrive at once, the watcher catches up from the change journal, or rescans when that is not possible.
  • After a restart. The NTFS change journal is read from the saved position, through the unprivileged journal interface, so no administrator rights are needed. Only the folders that changed are listed again. A drive without a usable journal is rescanned.
  • Checkpoints. Every 5 minutes, when the index changed, the journal positions are refreshed and names.idx and content.idx are saved. They are saved again on exit. An index that was interrupted during a crawl or catch-up is never saved, so a later start does not trust a partial index.

The content index

The content indexer walks the content folders through the name index, so it does not crawl the disk again. It extracts the text of each file (see File formats) and records every trigram, a sequence of three case-folded characters, with the list of files that contain it. A content query first takes the trigrams of the pattern (for a regular expression, of its required literal parts) to find candidate files, applies the name filters, then reads each remaining candidate again on a few worker threads to find the exact lines. Files that turn out to be changed or deleted are queued for reindexing.

14Troubleshooting and FAQ

The hotkey does not open the bar

Another program may own Alt+Shift+Space. sgcFSearch then falls back to Win+Shift+F, then to Ctrl+Alt+F. To see which one is active, open the tray menu (the hotkey is shown next to Search) or the log:

app: hotkey Alt+Shift+Space not available, error 1409
app: hotkey Win+Shift+F active

Two other messages can appear: app: invalid hotkey "..." when the setting cannot be parsed, and app: no global hotkey available when none of the three could be registered.

Choose a free combination in the Folders dialog. Without any hotkey, open the bar from the tray icon or with sgcfs show.

Where is the log?

%LOCALAPPDATA%\sgcFSearch\daemon.log. The tray menu item Open log opens it and sgcfs status prints its path. It holds starts and stops, the hotkey, watcher and journal events, and errors. At 2 MB it moves to daemon.log.old.

How do I rebuild the index?

  1. Quit sgcFSearch from the tray menu, or run sgcfs stop.
  2. Delete names.idx from the data folder to rebuild the name index. Delete content.idx to rebuild the content index.
  3. Start sgcFSearch again. It crawls the drives as on the first run.

What happens when I start sgcFSearch twice?

Only one instance runs per user. A second start does not build another index: it asks the running instance to show its search bar and exits. Started with --background, the second instance exits silently.

A file I know exists is not found

  • Check the state. During the first crawl the index is still partial.
  • Check the skip list and the Drives setting in the Folders dialog. Only fixed drives are indexed, network shares and removable drives are not part of the default set.
  • Folders your account cannot open (access denied) are listed, but their contents are not.
  • Junctions, symbolic links and mount points are not followed. Search for the file at its real location.
  • Words match the name, not the path. Use a path token, in: or path: for folder names.
  • ext:, type: (except folders) and size: (except size:empty) match files only. in: matches the contents of the folder, not the folder itself.
  • Look at the status line for a warning about an ignored filter value.

A text is not found inside a file

  • The file must be below a content folder (default: your user folder).
  • It must not be larger than content_max_size_mb (default 16 MB).
  • It must not be inside an excluded folder such as AppData, node_modules or .git (see Limits and exclusions).
  • Online-only cloud files are not read. Make the file available offline to have it indexed.
  • PDF and legacy Office files need a Windows IFilter for their extension.
  • After a start, the content indexer may still be reading files: watch for N files being read in the tray tooltip, or content pending in sgcfs status.
  • Content search ignores case, unless case:yes or the content_case setting makes it case-sensitive.
  • Plain words next to a content filter must match the file name.

Why does the bar show lines from inside files?

No file or folder name matched your words, so the content fallback searched the content folders instead. The status line says so.

sgcfs says "sgcFSearch is not running"

status and stop do not start the app. Start sgcFSearch.exe, or run any search or sgcfs show, which start it in the background. If the start fails, check that sgcFSearch.exe is in the same folder as sgcfs.exe.

My manual changes to config.json have no effect

The settings are read at start. Run sgcfs stop and start sgcFSearch again, or use the Folders dialog, which restarts it for you.

  • content_case setting in config.json: insensitive (default), smart (the previous behaviour) or sensitive. The setting is kept across updates.

1.0.2, November 2026

  • Search bar: the results list no longer flickers or jumps back to the start when the index changes. A refresh with unchanged rows leaves the list alone, and a refresh with changed rows keeps the scroll position and the selected row.

1.0.1, November 2026

  • Wildcards in name words: * matches any run of characters and ? one character, matched against the whole name, in addition to the existing syntax.
